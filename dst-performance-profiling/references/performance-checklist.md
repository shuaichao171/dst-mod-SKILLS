# 性能检查顺序

## 先分类

- 服务器 tick lag
- 客户端渲染或 UI
- 网络发送与 dirty
- 世界生成
- 启动或载入
- 长时间实体与任务泄漏

## 高频热点

1. OnUpdate 和 static update。
2. 每秒多次 DoPeriodicTask。
3. 无标签或大半径 FindEntities。
4. Brain 条件与目标搜索。
5. SG timeline 和事件风暴。
6. 每帧临时表、闭包和字符串。
7. 高频 netvar set 与 RPC。
8. 没有结束的 FX、子实体、任务和 Widget。

## 优化手段

先减少工作次数，再优化单次工作：

- 事件替代轮询
- 延长检查周期
- 使用 MUST、CANT、ONEOF 标签
- 使用距离平方
- 分桶或世界管理器
- 缓存稳定值并定义失效
- Brain 与实体 Sleep
- 合并网络状态
- 停止隐藏 UI 更新

## 结果记录

记录相同场景的实体数、玩家数、采样时间、平均值、峰值和正确性。优化后重新测试极端数量、长时间运行和玩家加入离开。
